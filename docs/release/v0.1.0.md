## Summary

The first release of passalong: a lightweight clipboard and file sharing
tool for macOS and Linux. One machine runs a plain OpenSSH server with a
storage directory; every other device sends clipboard text and files there,
lists what is stored, and loads items back.

## Changes

- Five commands: `clipboard` (with `--stdin`), `file`, `list` (with
  `--json`), `load`, and `serve`.
- SSH/SFTP backend with a pinned server host key, public-key authentication,
  and a connect timeout; a `local` backend for mounted shares.
- Storage layout with atomic publish through `tmp/`, deduplication by
  content key, and time-sortable ids (`<hex seconds>-<content key>`).
- `load` verifies SHA-256 and size before replacing anything and sanitises
  server-supplied file names.
- `serve` watches the clipboard and a drop folder, retries with reconnection,
  and stops cleanly on Ctrl-C or SIGTERM; systemd and launchd examples.
- Syslog-style logging with correlation ids and a field allow-list.
- Configuration lookup in six positions with validation that names the key.
- Workspace of `passalong-core`, `passalong-ssh`, and `passalong-cli`;
  `just` recipes, pre-commit hook, GitHub Actions CI, Dockerfile.

## Configuration

`config.toml` keys introduced in this release:

| Section | Keys |
|---|---|
| `[client]` | `device_name`, `log_level` |
| `[server]` | `kind` (`ssh` or `local`) |
| `[server.ssh]` | `host`, `port`, `user`, `host_key`, `identity_file`, `remote_path`, `connect_timeout_secs` |
| `[server.local]` | `path` |
| `[serve]` | `drop_folder`, `clipboard_poll_interval_ms`, `file_stable_wait_ms`, `after_send` |

Environment variables: `PASSALONG_CONFIG_FILE`,
`PASSALONG_SSH_KEY_PASSPHRASE`, `PASSALONG_LOG_LEVEL`.

## Upgrade notes

First release; there is nothing to upgrade from. v0.1.0 was not published
to crates.io and has no prebuilt binaries. Install it from the tag:

```sh
cargo install --locked --git https://github.com/joelee/passalong --tag v0.1.0 passalong-cli
```

## Known limitations

- Clipboard support is text only.
- On Linux, text that `load` puts on the clipboard survives only if a
  clipboard manager takes it over within 2 seconds.
- No encryption at rest, and no `delete` or `prune`.
