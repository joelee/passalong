Released 2026-09-12. Tag `v0.1.1` points at `df32a81`, the merge of
[PR #2](https://github.com/joelee/passalong/pull/2). Delivered by
[Delivery Plan 00002](../plans/00002-V0_1_1_CLI_Stabilisation.md). GitHub
release: <https://github.com/joelee/passalong/releases/tag/v0.1.1>, with

`passalong`, `passalong-core`, and `passalong-ssh` 0.1.1 are on crates.io.

## Summary

v0.1.1 completes the command-line client for SSH servers. It adds commands
to delete and expire items, a guided `init`, and a background `serve`. It
keeps text loaded on Linux on the clipboard, and adds a tested Docker setup
for the server. From this release, passalong is on crates.io and each
GitHub release carries prebuilt binaries.

## Changes

- `passalong delete <ID>...` removes items. Every id is resolved before
  anything is deleted, so a typo deletes nothing.
- `passalong prune --older-than <AGE> --keep <N>` deletes old items after
  confirmation, with `--dry-run` and `--yes`. It also clears upload
  leftovers older than an hour from the server.
- `passalong init` writes a config file for an SSH server. It fetches the
  server's host key, pins it only after you confirm the fingerprint, and
  tests the connection. Every answer can also be given as a flag.
- `passalong serve --daemon` runs `serve` in the background with a log
  file. `serve --status` and `serve --stop` manage it, and a second `serve`
  on the same machine is refused.
- On Linux, text that `load` puts on the clipboard stays there after the
  command exits, without a clipboard manager.
- `serve` retries a dropped file it could not read once the file changes,
  instead of skipping it until restart.
- A config location that exists but cannot be read is reported as such,
  instead of "no config file found".
- `docs/docker-ssh-server-setup.md` and `deploy/ssh-server/` run the SSH
  server in Docker with the storage on the host; `just test-deploy` tests
  the guide end to end.
- The CLI package is now named `passalong`, and all three crates carry
  crates.io metadata.
- CI audits dependencies with `cargo deny` and runs the desktop clipboard
  tests under Xvfb. Pushing a `vX.Y.Z` tag builds binaries, creates the
  GitHub release, and publishes the crates.

## Configuration

No `config.toml` keys or environment variables were added or changed.
`passalong init` writes the existing keys. Background `serve` keeps two
files:

| Platform | Pid file | Log file |
|---|---|---|
| Linux | `${XDG_STATE_HOME:-~/.local/state}/passalong/serve.pid` | `${XDG_STATE_HOME:-~/.local/state}/passalong/serve.log` |
| macOS | `~/Library/Application Support/passalong/serve.pid` | `~/Library/Logs/passalong/serve.log` |

## Upgrade notes

The CLI package was renamed from `passalong-cli` to `passalong`; the
binary is still `passalong`. Remove an earlier install first, because
cargo will not replace a binary owned by another package:

```sh
cargo uninstall passalong-cli
cargo install --locked passalong
```

Alternatively, download the archive for your platform from the GitHub
release and check it against its `.sha256` file.

Stored items and config files from v0.1.0 work unchanged. If `serve` runs
under systemd or launchd, keep using the unit or switch to
`serve --daemon`, not both: the second one is refused.

## Known limitations

- Clipboard support is text only.
- No encryption at rest.
- One-shot commands open a new SSH connection each time.
