# passalong v0.1.2

Finalised 2026-09-13 for the `v0.1.2` tag, from the branch
`feature/00003-v0.1.2`. Delivered by
[Delivery Plan 00003](../plans/00003-V0_1_2_Images_Pull_And_Downloads.md).
GitHub release: <https://github.com/joelee/passalong/releases/tag/v0.1.2>.

## Summary

v0.1.2 makes sharing between devices practical. Clipboard images travel
like text, `serve` can pull what other devices send, files download into
`~/Downloads`, `passalong cat` prints an item, and a short id that matches
several items asks which one you mean. Default builds no longer contain the
`rsa` crate and its unfixed advisory, and `cargo deny` now rejects new
duplicate dependencies.

## Changes

- `passalong cat <ID>` prints an item to standard output exactly as stored,
  verifying its SHA-256. On a terminal, binary items need `--force`.
- `passalong load <ID>` without a destination downloads files into
  `client.download_dir`, `~/Downloads` by default, created if missing. An
  existing name is kept and the download is numbered, as in
  `report (1).pdf`, unless `--force` is given.
- When an id prefix matches several items, `load`, `cat`, and `delete` list
  up to 9 of them on a terminal and ask which one you mean. Scripts still get
  the error listing every match.
- Clipboard images: `passalong clipboard` sends the image when the clipboard
  holds no text, `load` puts it back on the clipboard or writes the PNG with
  a destination, `cat` prints the PNG, and `list` shows kind `image`. On
  Linux, a loaded image stays on the clipboard after `load` exits.
- `serve` sends clipboard images too, once per new image; set
  `serve.clipboard_images = false` to turn this off.
- Pull mode: with `serve.pull = true`, `serve` applies items sent by other
  devices. The newest text or image goes to the clipboard, and files go into
  `client.download_dir` when it exists. Nothing pulled is sent back.
- RSA identity files and `ssh-rsa` host keys need a build with the `rsa`
  feature. Default builds, the release binaries, and `cargo install
  passalong` leave it out because of RUSTSEC-2023-0071.
- `cargo deny` fails on any new duplicate dependency version; the remaining
  duplicates are listed in `deny.toml` with the dependency that needs each.
- The release workflow refuses to run unless the changelog, release notes,
  and README are final for the tag. It publishes to crates.io only after a
  maintainer approves the `release` environment, and creates the GitHub
  release only after publishing succeeds.

## Configuration

New `config.toml` keys; every other key is unchanged.

| Key | Default | Meaning |
|---|---|---|
| `client.download_dir` | `~/Downloads` | Where `load` puts files without a destination, and where pull mode writes files if it exists |
| `serve.clipboard_images` | `true` | Also send clipboard images |
| `serve.pull` | `false` | Apply items sent by other devices |
| `serve.pull_interval_ms` | `5000` | How often pull mode checks, 1000 to 3600000 |

## Upgrade notes

- **RSA keys.** If you log in with an RSA key, or pin an `ssh-rsa` host
  key, reinstall with the `rsa` feature or switch to an Ed25519 key:

  ```sh
  cargo install --locked passalong --features rsa
  ```

  Without it, passalong stops with an error that names the feature.
- **`load` without a destination.** File items are now downloaded into
  `~/Downloads` instead of being refused. Scripts that relied on the error
  should pass a destination.
- **Mixed versions.** Clipboard images are stored as PNG files with an extra
  `origin` field in `meta.json`. Clients older than v0.1.2 ignore the field
  and see an ordinary PNG file they can download.
- **Config without `HOME`.** The default `client.download_dir` needs `HOME`,
  as the default `serve.drop_folder` already did; set absolute paths when
  running without it.
- Pull mode is off until you enable it, so upgrading changes nothing for
  `serve` on its own.

## Known limitations

- Pull mode orders items by their creation time, so keep the devices'
  clocks in sync; an item from a device whose clock runs behind can be
  missed.
- Clipboard images on Linux need X11 or a Wayland compositor with the
  `wlr-data-control` protocol. CI exercises images under X11 only.
- No encryption at rest, and one-shot commands open a new SSH connection
  each time.
