# passalong v0.1.3

Draft for the `v0.1.3` tag. Delivered by
[Delivery Plan 00004](https://github.com/joelee/passalong/blob/v0.1.3/docs/plans/00004-V0_1_3_Review_Fixes_And_Pull_Ids.md).

## Summary

v0.1.3 is a small release that fixes what the v0.1.2 release and its code
review found. Pull mode no longer depends on device clocks, choosing
between ambiguous ids stays fast on large stores, two downloads of the same
name can no longer overwrite each other, and release notes link to their
plans correctly.

## Changes

- Pull mode remembers the item ids it has handled instead of comparing
  creation times, so an item from a device whose clock runs behind is still
  applied, once. Each check reads one directory listing and only the new
  items' metadata.
- When an id prefix matches several items, the choice prompt reads the
  metadata of the items it shows, at most 9, instead of every item in the
  store (Code Review 00001, REV-00001-MED-01).
- `load` and pull mode choose a download's file name only once its content
  is complete and verified, and link it into place without replacing
  anything, so two downloads of the same name at the same moment always
  keep both files (REV-00001-LOW-01).
- Release notes link to their delivery plans with absolute URLs pinned to
  the release tag, and the release check rejects relative links
  ([issue #4](https://github.com/joelee/passalong/issues/4)).
- `passalong-core` adds `Store::get_meta` and `Store::list_ids`, both with
  default implementations, and deprecates `Store::newest_id` and
  `download::free_target`.

## Upgrade notes

- No action is needed. Stored items and config files from v0.1.2 work
  unchanged.
- Code that implements `passalong_core::store::Store` keeps compiling,
  because the new methods have default implementations. A backend can
  override `get_meta` and `list_ids` with cheaper versions.
- Code that calls `Store::newest_id` or `download::free_target` gets a
  deprecation warning; use `list_ids` and `download_into` instead.
- The published v0.1.1 and v0.1.2 release pages still carry a broken link
  to their plan; the plans are in
  [docs/plans](https://github.com/joelee/passalong/tree/main/docs/plans).

## Known limitations

- Clipboard images on Linux need X11 or a Wayland compositor with the
  `wlr-data-control` protocol. CI exercises images under X11 only.
- No encryption at rest, and one-shot commands open a new SSH connection
  each time.
