# passalong v0.1.4

Draft for the `v0.1.4` tag. Delivered by
[Delivery Plan 00005](https://github.com/joelee/passalong/blob/v0.1.4/docs/plans/00005-V0_1_4_Service_Check_Get_Quiet.md).

## Summary

v0.1.4 rounds off the command line. `passalong install-service` starts
`serve` at login under systemd or launchd, `passalong check` tests the whole
setup, `passalong get` shows an item's metadata, and `--quiet` makes every
command quiet enough for scripts. `passalong cat` prints only the item, the
README's links work on crates.io, and the Release workflow runs without
error annotations.

## Changes

- `passalong install-service` writes a systemd user unit on Linux or a
  launchd agent on macOS that runs this binary's `serve` from your home
  directory, then enables and starts it. `--no-start` only writes the unit,
  `--force` replaces one that differs, and `--uninstall` stops and removes
  it. It will not start a service while another `serve` runs.
- `passalong check` checks the config, the connection with its pinned host
  key, and that the store can be read and written, one line per check. The
  write test uses a probe under the store's `tmp/` folder, which listings
  and pull mode never see.
- `passalong get <ID>` prints an item's metadata without reading its
  content; `--json` prints the same object as `list --json`.
- `-q`/`--quiet` prints nothing but errors and prompts, and logs only errors
  unless a level is set with `--log-level` or `PASSALONG_LOG_LEVEL`. `cat`
  still prints the item, so scripts can rely on the exit code.
- `passalong cat` prints only the item: its log record moved to the
  `verbose` level, so it no longer follows the content on the terminal.
- The README's links are absolute, so they work on
  [crates.io](https://crates.io/crates/passalong), which resolved the
  relative ones against the CLI crate's folder. `just check` now runs
  `scripts/check-links.sh`, which also fails on a missing link target or
  heading. The "How it works" diagram is a Mermaid diagram.
- The Release workflow removes `target/package` before the build cache is
  saved, which ends the 20 error annotations of the v0.1.3 run, and its
  artifact actions run on Node.js 24. Dependabot proposes action updates
  monthly.
- The units in `docs/service/` run from the home directory, so a `~/.env`
  is found. The launchd agent logs to `~/Library/Logs/passalong/serve.log`,
  like `serve --daemon`, and is loaded with `launchctl bootstrap`.
- `passalong-core` adds `Store::probe_write` and `WriteProbe`; the default
  implementation reports `NotSupported`.

## Configuration

No `config.toml` keys or environment variables were added or changed.

## Upgrade notes

- No action is needed. Stored items and config files from v0.1.3 work
  unchanged.
- If you installed `docs/service/passalong-serve.service` by hand, replace
  it with one for this binary: stop it with
  `systemctl --user stop passalong-serve.service`, then run
  `passalong install-service --force`.
- On macOS, `passalong install-service --force` replaces a hand-installed
  agent, booting the old one out first. The agent now logs to
  `~/Library/Logs/passalong/serve.log` instead of
  `~/Library/Logs/passalong-serve.log`.
- Code that implements `passalong_core::store::Store` keeps compiling. A
  backend can override `probe_write` so that `passalong check` tests
  writing.

## Known limitations

- `install-service` supports systemd and launchd only, and is tested
  against fakes of `systemctl` and `launchctl`, not real service managers.
- Clipboard images on Linux need X11 or a Wayland compositor with the
  `wlr-data-control` protocol. CI exercises images under X11 only.
- No encryption at rest, and one-shot commands open a new SSH connection
  each time.
