## Summary

v0.1.5 is the first release since v0.1.3. v0.1.4 was merged but not
released, so its changes ship here too.

- **Idle CPU fixed:** an idle `serve` no longer keeps more than a CPU core
  busy.
- **New `passalong choose`:** picks items from a full-screen list.
- **Service commands:** `passalong service-install` and
  `passalong service-remove` run `serve` as a systemd or launchd service.
- **Checking and scripting:** `passalong check` tests the whole setup and
  reports whether `serve` runs, `passalong get` shows an item's metadata,
  and `--quiet` suits scripts.
- **Project maintenance:** the README's links work on crates.io, the
  Release workflow runs without error annotations, and CI checks that the
  library crates build for Android.

## Changes

### New in v0.1.5

- **An idle `serve` no longer spins.**
  - The drop-folder watcher reacted to every inotify event. Each scan
    opens the folder, which caused events that started the next scan.
  - It now reacts only to files being created, written, renamed, or
    removed.
  - Idle CPU fell from about 136 % to 0.00 % (see "Idle cost").
- **`passalong choose`** opens a full-screen list of the stored items,
  newest first, with id, kind, name or preview, size, device, and age.
  - `/` filters the list.
  - Enter loads the selected item and `c` prints it. Each closes the list
    first, so the output stays in the terminal.
  - `g` shows the item's metadata in a scrollable dialog over the list.
  - `d` deletes after a `y` and shows the list read again from the store;
    `r` reloads, showing `Reloading...` until it is done; `q` quits.
  - `?` shows the passalong version, what it is, and every key.
- **`passalong service-install` and `passalong service-remove`.**
  - `service-install` writes a systemd user unit on Linux or a launchd
    agent on macOS that runs this binary's `serve` from your home folder,
    then enables and starts it.
  - `--no-start` only writes the unit, and `--force` replaces one that
    differs.
  - `service-remove` stops and removes the unit.
  - v0.1.4 called the command `install-service --uninstall`; it was never
    released, so there is no alias.
- **`passalong check` ends with a `serve` line**, saying whether `serve` is
  running and with which pid. The line is informational and never fails.
- **CI builds `passalong-core` and `passalong-ssh` for Android
  (aarch64).** `just android-check` runs the same check locally with an
  Android NDK; the developer guide lists the prerequisites.

### From the unreleased v0.1.4

- **`passalong check`** checks the config, the connection with its pinned
  host key, and that the store can be read and written, one line per
  check. The write test uses a probe under the store's `tmp/` folder,
  which listings and pull mode never see.
- **`passalong get <ID>`** prints an item's metadata without reading its
  content. `--json` prints the same object as `list --json`.
- **`-q`/`--quiet`** prints nothing but errors and prompts. Logging drops to
  errors only, unless `--log-level` or `PASSALONG_LOG_LEVEL` sets a level.
  `cat` still prints the item.
- **`passalong cat`** prints only the item. Its log record moved to the
  `verbose` level.
- **The README's links are absolute**, so they work on
  [crates.io](https://crates.io/crates/passalong).
  - `just check` runs `scripts/check-links.sh`, which also fails on a
    missing link target or heading.
  - The "How it works" diagram is a Mermaid diagram.
- **The Release workflow runs without error annotations.**
  - It removes `target/package` before the build cache is saved.
  - Its artifact actions run on Node.js 24.
  - Dependabot proposes action updates monthly.
- **The units in `docs/service/` run from the home folder**, so a `~/.env`
  is found. The launchd agent logs to `~/Library/Logs/passalong/serve.log`,
  like `serve --daemon`.
- **`passalong-core` adds `Store::probe_write` and `WriteProbe`.** The
  default implementation reports `NotSupported`.

## Idle cost

A sandboxed release-build `serve` was measured over 20 s after 10 s of
start-up. It had a temporary home, a local store, and an empty drop
folder.

| Build | Clipboard | CPU | Threads | Context switches |
|---|---|---|---|---|
| v0.1.4 | none | 136.45 % | 37 | 395,057/s |
| v0.1.5 | none | 0.00 % | 35 | 2/s |
| v0.1.4 | X11, holding text (container) | 136.70 % | 38 | 661,286/s |
| v0.1.5 | X11, holding text (container) | 0.10 % | 36 | 16/s |

Idle cost is below 1 % CPU, so the runtime and the clipboard polling were
left as they are. The idle threads are mostly the async runtime's workers.

## Configuration

- No `config.toml` keys or environment variables were added or changed.
- `-q`/`--quiet` is a new global option.

## Dependencies

- `passalong` now depends on ratatui 0.30, without default features, with
  its crossterm backend.
  - It adds about 35 crates and 299 KiB (3 %) to the release binary.
  - `deny.toml` allows two duplicate versions it needs: `foldhash` 0.1.5
    and `hashbrown` 0.16.1.
- The library crates' public API only gains `Store::probe_write`.

## Upgrade notes

- **From v0.1.3:** no action is needed. Stored items and config files work
  unchanged.
- **Hand-installed units from `docs/service/`:** stop the service first,
  then run `passalong service-install --force`.
  - Linux: stop it with `systemctl --user stop passalong-serve.service`.
  - macOS: stop it with
    `launchctl bootout gui/$(id -u)/com.passalong.serve`.
  - The macOS agent now logs to `~/Library/Logs/passalong/serve.log`.
- **Store implementations:** code that implements
  `passalong_core::store::Store` keeps compiling. Override `probe_write` so
  that `passalong check` tests writing.

## Known limitations

- **Service managers:** `service-install` supports systemd and launchd
  only. launchd is tested only against a fake `launchctl`.
- **Clipboard images on Linux:** they need X11 or a Wayland compositor with
  the `wlr-data-control` protocol.
- **Security and connections:** there is no encryption at rest, and
  one-shot commands open a new SSH connection each time.
