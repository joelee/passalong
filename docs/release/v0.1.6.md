# passalong v0.1.6

Draft for the `v0.1.6` tag, from the branch `feature/00007-v0.1.6`.
Delivered by
[Delivery Plan 00007](https://github.com/joelee/passalong/blob/v0.1.6/docs/plans/00007-V0_1_6_List_Cache_And_Homebrew.md).

## Summary

- **List cache:** with an SSH server, `serve` keeps a local copy of the
  item list, so `passalong list` and `passalong choose` show it without
  waiting for the server.
- **Homebrew:** `brew install joelee/oss/passalong` builds the crates.io
  release.
- **Write timing:** `passalong check` reports how long its 128-byte write
  probe took.

## Changes

### New in v0.1.6

- **`serve` keeps a list cache**, with the `ssh` backend and
  `serve.list_cache` on, as it is by default.
  - The cache is `list-cache.json` in `serve`'s state folder, next to
    `serve.pid`. Only you can read it, and it is written through a
    temporary file and a rename, so a reader never sees half a file.
  - `serve` refreshes it at start and then every
    `serve.list_cache_check_secs`, 60 s by default. A refresh lists the
    item ids once and reads the metadata of new ids only. It uses a
    connection of its own, and after an error it keeps the last good file
    and reconnects at the next check.
  - A cache is used only for the server it lists, and only for twice the
    check interval, 2 minutes by default.
- **`passalong list`** prints a fresh cache without connecting.
  - The output is the same as from the server; `--log-level verbose` says
    which was used.
  - `--nocache` reads the server and rewrites the cache.
- **Commands keep the cache current.**
  - `file`, `clipboard`, `delete`, and `prune` add their own changes to it
    without another round trip.
  - `load`, `cat`, and `get` refresh it after their output.
  - `serve`'s own sends appear at its next refresh.
  - A cache problem is logged at verbose level and never fails a command.
- **`passalong choose`** opens from a fresh cache and says how old it is,
  such as `cached 30 s ago`.
  - `r` reloads the cache, or reads the server when the cache is not
    usable.
  - The new `R` reads the server and rewrites the cache.
  - The help lists `R`.
- **`passalong check`** writes a 128-byte probe and reports how long
  writing and removing it took, and the rate:
  `wrote and removed a 128-byte probe in 184 ms (696 B/s)`. With so little
  data, the time mostly shows round trips, not bandwidth.
- **Homebrew formula** `joelee/oss/passalong` in
  [joelee/homebrew-oss](https://github.com/joelee/homebrew-oss), built from
  the crates.io crate.
  - `scripts/update-homebrew-formula.sh vX.Y.Z` points it at a new
    release.
  - The release workflow ends with that step.

## List cache timing

Measured with a release build against the Docker OpenSSH server that the
integration tests use, on the same machine, so with almost no network
latency. Each figure is the median of three runs.

| Items | `list --nocache` (reads the server) | `list` (fresh cache) |
|---|---|---|
| 10 | 122 ms | 4 ms |
| 100 | 140 ms | 4 ms |

Without latency, most of the 120 ms is the SSH handshake. Reading the
server also costs at least one SFTP round trip per item, to open and read
its `meta.json`, so over a slow link the time grows with the store: 100
items over a link with 50 ms round trips take 5 s or more, in line with the
3 to 5 s seen over mobile connections. A fresh cache takes the same few
milliseconds on any link, because `list` makes no connection.

## Configuration

- **New `[serve]` keys:**
  - `list_cache` (boolean, default `true`);
  - `list_cache_check_secs` (integer, default 60, 10 to 86400).
- **New file:** `list-cache.json`, in
  `${XDG_STATE_HOME:-~/.local/state}/passalong/` on Linux and in
  `~/Library/Application Support/passalong/` on macOS.
- **New option:** `passalong list --nocache`.

## Library changes

- **`passalong_core::cache` is new:** `ListCache`, `refresh_loop`,
  `CACHE_FILE`, `CACHE_VERSION`, and `max_age`.
- **`ServeConfig` gains two public fields**, `list_cache` and
  `list_cache_check_secs`. Code that builds a `ServeConfig` literal must
  set them.
- **`passalong_core::store::PROBE_BYTES` is new**, and
  `FsStore::probe_write` writes that many bytes.

## Upgrade notes

- **From v0.1.5:** no action is needed. Stored items and config files work
  unchanged.
- **A running `serve`** keeps no cache until it is restarted with the new
  binary: `passalong serve --stop` and start it again, or restart the
  service. Until then, `list` reads the server and writes the cache itself.
- **To turn the cache off,** set `serve.list_cache = false`.

## Known limitations

- **`choose` still connects first**, because its actions need the store.
  The cache saves the listing time, not the connection time.
- **Reading the server is unchanged:** `list --nocache`, `R`, and a listing
  without a fresh cache still read each item's metadata in turn.
- **Homebrew builds from source**, so installing needs Homebrew's Rust
  toolchain and a few minutes. Homebrew 7 and later also ask you to trust
  the tap once: `brew trust joelee/oss`, then `brew tap joelee/oss`.
- **Security and connections:** there is no encryption at rest, which is
  planned for v0.1.7, and one-shot commands open a new SSH connection each
  time.
