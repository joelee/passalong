# passalong v0.2.0

Draft for the `v0.2.0` tag, from the branch `feature/00008-v0.2.0`.
Delivered by
[Delivery Plan 00008](https://github.com/joelee/passalong/blob/v0.2.0/docs/plans/00008-V0_1_7_Encryption_At_Rest.md).

## Summary

- **Encryption at rest:** a store can be encrypted on the devices that use
  it, so an SSH server, or the service behind a synced `local` folder,
  stores only sealed items. `passalong encrypt` sets it up, `--join` adds a
  device, `--rotate` shuts out a lost one, and `--recover` finishes or
  undoes an interrupted re-encryption.
- **Breaking:** clients before v0.2.0 stop working with an encrypted store,
  and the library's public API changes; see Upgrade notes and Library
  changes.

## Changes

### New in v0.2.0

- **`passalong encrypt`** shows six generated words, has them typed back,
  and encrypts the store. A store with items is migrated, each item
  re-encrypted and checked, or started fresh, leaving the items
  unencrypted in `plain/` until `passalong prune --plain`. On an encrypted
  store it changes the words without re-encrypting anything.
- **`passalong encrypt --join`** gives a device the store's key; `init`
  does the same when it finds an encrypted store, and offers to encrypt an
  empty one.
- **`passalong encrypt --rotate`** replaces the key and words and
  re-encrypts every item; every other device must join again.
- **`passalong encrypt --recover`** finishes or undoes a migration or
  rotation that was interrupted. A re-encryption holds a lock on the
  server, keeps each item's time and metadata, checks every copy before
  the new key takes over, and resumes without uploading anything twice.
- **`passalong check`** gains an `encryption` line.
- **`passalong prune --plain`** removes the unencrypted items a fresh start
  left, and `list` warns while any remain.
- **`serve`** works with encrypted stores: pull mode starts afresh when the
  key changes, and the list cache names the key it was written with.

## Security

- Content, file names, previews, MIME types, sizes, SHA-256 digests, and
  device names are sealed with AES-256-GCM, per item and per 64 KiB record.
  Ids use a keyed content key, so the storage cannot confirm guesses about
  short clipboard text.
- The data key is wrapped with Argon2id (64 MiB, t=3, p=4) from six words of
  the EFF large word list, about 77.5 bits; the words are always generated.
- Each device keeps its key in `client.key_file`, mode 0600, refused when
  others can read it or inside a git work tree that does not ignore it.
- The storage still sees creation times, the number of items, their
  approximate sizes, which items share content, and access times.
- The words and the devices' key files are the only way to the items.

## Configuration

- `client.key_file`: where this device keeps an encrypted store's key.
  Default: `store.key` beside the default config file.

## Library changes

These changes break code built against 0.1:

- `ClientConfig` has a new field, `key_file`.
- `StoreError` has a new variant, `Encryption`.
- `StoreError`, `FsError`, `ConfigError`, `ModelError`, `Config`,
  `ClientConfig`, `ServerConfig`, `SshConfig`, `LocalConfig`, and
  `ServeConfig` are `#[non_exhaustive]`: build configs by parsing, and give
  matches a wildcard arm.

Additions: the `crypto` and `encryption` modules; `FsStore::sealed`;
`RemoteFs::create_dir` and `RemoteFs::remove_file`, with defaults;
`Store::key_id` and `Store::content_key`, with defaults;
`BackendRegistry::register_fs` and `BackendRegistry::open_fs`; `SubFs`;
`NewItem::finish_keyed`; `ContentDigest::new`; and in `passalong-ssh`,
`open_ssh_fs`.

## Upgrade notes

- **Upgrade every device to v0.2.0 before encrypting a store.** A device on
  v0.1.6 or earlier fails against an encrypted store, without writing into
  it, until it is upgraded and joins.
- Plaintext stores are unchanged, and nothing is encrypted until you run
  `passalong encrypt`.
- A list cache from v0.1.6 is read once more from the server.
- Library users: see Library changes.

## Known limitations

- An encrypted store cannot be turned back into a plaintext one.
- Creation times, item counts, and sizes stay visible to the storage.
- Changing the words does not lock out a device that holds the key; rotate
  the key for that.
- Synced folders were checked by hand with one provider only.
- Windows is not supported yet.
